# Milestone 3 - Qwen3-VL Mask-Pair Scoring

Milestone 3 adds semantic mask-pair scoring with `Qwen/Qwen3-VL-2B-Instruct` to the MaskClustering pipeline. It supports the base model as a zero-shot scorer and the LoRA-fine-tuned vision classifier used in this project.

See [Fine_Tuning.md](Fine_Tuning.md) for the detailed design of candidate generation, rendering, fine-tuning, and evaluation.

## Repository layout

The examples assume this layout:

```text
<repo>/
|-- data/replica/                         # Replica RGB-D data and generated masks
|-- checkpoints/qwen/checkpoint-625/     # Fine-tuned Qwen adapter and score head
|-- MaskClustering/
`-- Project/Milestone_3/
```

All commands below are executed from the repository root. On Linux or macOS, locate it portably with:

```bash
cd "$(git rev-parse --show-toplevel)"
```

No user-specific `/home`, `/rhome`, or `/cluster` paths are required.

## Environments

The geometry-heavy candidate-building phase and the Qwen phase use separate environments because their dependencies differ.

| Script | Used for |
|---|---|
| `start_env.sh` | MaskClustering, Open3D, and PyTorch3D operations |
| `qwen_env.sh` | Qwen3-VL inference, evaluation, and LoRA fine-tuning |

Create the environments from the repository root:

```bash
bash Project/Milestone_3/start_env.sh
bash Project/Milestone_3/qwen_env.sh Project/env/qwen_env
```

`start_env.sh` may download and install a local CUDA toolkit if CUDA 11.8 is not already available. On a managed cluster, an existing compatible MaskClustering environment can be used instead.

## 1. Build candidate mask pairs

Run this step in the MaskClustering environment. The final pipeline uses a high-recall OR rule: a pair is retained when its geometric overlap or its view-consensus score passes the configured criterion.

```bash
python Project/Milestone_3/build_qwen_candidates.py \
    --scene room0 \
    --filter-mode or_rule \
    --depth-overlap-threshold 0.05 \
    --vc-threshold 0.60
```

Default outputs:

```text
Project/Milestone_3/data/candidates/room0_qwen_candidates.csv
Project/Milestone_3/data/candidates/room0_qwen_candidates.summary.json
```

Useful arguments:

| Argument | Description |
|---|---|
| `--scene` | Replica scene name |
| `--filter-mode` | `iou`, `any_asymmetric`, or `or_rule` |
| `--depth-overlap-threshold` | Minimum geometric-overlap threshold; default `0.05` |
| `--vc-threshold` | View-consensus threshold for `or_rule`; default `0.60` |
| `--train` | Enable training selection and optional negative balancing |
| `--negative-ratio` | Optional maximum number of negatives per positive in training mode |
| `--eval` | Keep all filter-passing candidates; this is the default |
| `--output` | Optional output CSV; relative paths are resolved from the repository root |

## 2. Load and render candidate pairs

Run this step in the Qwen environment. `load_data_training` reads a candidate CSV and renders the two mask views expected by the model.

```python
from load_training_data import load_data_training

samples = load_data_training(
    pool_path="Project/Milestone_3/data/candidates/room0_qwen_candidates.csv",
    masks_root="data",
    rgb_root="data/replica",
    render_mode="outline",  # "outline", "filled", or "raw_mask"
    alpha=0.4,
)
```

When importing from an interactive session, either start Python from `Project/Milestone_3` or add that directory to `PYTHONPATH`.

## 3. Test one mask pair with the base model

Run in the Qwen environment:

```bash
python Project/Milestone_3/inference.py \
    --config Project/Milestone_3/config_stage1.yaml \
    --condition pair_only \
    --scene room0 \
    --masks-root data \
    --rgb-root data/replica \
    --frame-a 12 --mask-a 3 \
    --frame-b 47 --mask-b 5
```

The current inference interface supports `pair_only`. Available render modes are `outline`, `filled`, and `raw_mask`.

## 4. Evaluate the zero-shot model

```bash
python Project/Milestone_3/evaluate.py \
    --pool-path Project/Milestone_3/data/candidates/room0_qwen_candidates.csv \
    --masks-root data \
    --rgb-root data/replica \
    --batch-size 4 \
    --output Project/Milestone_3/results/eval_room0.json \
    --config Project/Milestone_3/config_stage1.yaml
```

`--pool-path` accepts one or more candidate CSV files generated by `build_qwen_candidates.py`.

## 5. Fine-tune the classifier

Run in the Qwen environment. The current project configuration applies LoRA to the final eight of the 27 vision-transformer blocks and trains a two-layer MLP score head.

```bash
python Project/Milestone_3/fine_tuning.py train \
    --pool-path Project/Milestone_3/data/candidates/room0_qwen_candidates.csv \
                Project/Milestone_3/data/candidates/office0_qwen_candidates.csv \
    --masks-root data \
    --rgb-root data/replica \
    --condition pair_only \
    --render-mode outline \
    --config Project/Milestone_3/config_stage1.yaml
```

Use `--val-pool-path` to provide held-out validation-scene CSV files. Training output is written to the `sft.output_dir` configured in `config_stage1.yaml`.

## 6. Score pairs with the fine-tuned model

The repository checkpoint layout documented in the root README can be used directly:

```bash
python Project/Milestone_3/fine_tuning.py score \
    --pool-path Project/Milestone_3/data/candidates/office1_qwen_candidates.csv \
    --masks-root data \
    --rgb-root data/replica \
    --condition pair_only \
    --render-mode outline \
    --adapter-path checkpoints/qwen/checkpoint-625 \
    --output Project/Milestone_3/results/score_office1.json \
    --config Project/Milestone_3/config_stage1.yaml
```

`--condition` and `--render-mode` must match the settings used to train the checkpoint.

## 7. Convert scores and run clustering

The helper scripts used by the downstream pipeline are:

| Script | Purpose |
|---|---|
| `candidates_to_pool.py` | Convert candidate CSV files to the legacy pair-pool format when required |
| `score_qwen_candidates.py` | Score a complete candidate CSV with the fine-tuned classifier |
| `convert_classifier_scores.py` | Convert classifier JSON output to pair-score CSV format |
| `run_qwen_clustering.py` | Create Qwen-score-based instance clusters |

Use `python <script> --help` for the current command-line arguments. Defaults are derived from the repository location rather than from a specific user or cluster filesystem.

## Outputs and checkpoints

Generated candidates, scores, and clustering results are stored below `Project/Milestone_3/data/`. Model artifacts belong below `checkpoints/` as described in the root README. Large generated files should normally be distributed as release artifacts rather than committed directly to Git.
